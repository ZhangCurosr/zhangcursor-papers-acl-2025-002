# 论文速读：ToolHop: A Query-Driven Benchmark for Evaluating Large Language Models in Multi-Hop Tool Use

## 一句话总结
本文提出了 **ToolHop**，一个面向**多跳工具使用（multi-hop tool use）**的查询驱动型评测基准，包含 995 个用户查询与 3,912 个可本地执行的工具，旨在严格评估大语言模型在复杂多步工具调用中的理解、推理与函数调用能力。

## 研究问题与动机
1. **现有工具使用评测缺乏可靠的多跳评估基准**：多数工作聚焦于单步工具调用或依赖先进模型进行过程分析，无法可靠评估多跳推理能力。
2. **工具驱动的数据构建方法存在根本缺陷**：传统方法先收集工具再模拟查询，无法保证工具间存在真实依赖关系，且查询往往不能体现真正的多跳推理。
3. **缺少可验证答案与详细反馈机制**：以往工作因无预定义答案而依赖模型打分，引入模型偏差与评估误差；同时缺乏对错误调用的详细信息反馈，难以评估模型的纠错能力。
4. **多跳工具使用是迈向通用智能的关键能力**：该任务要求模型将复杂查询分解为原子子查询、顺序调用工具并迭代获取结果，综合考察理解、推理与函数调用能力。

## 核心贡献（创新点）
1. **提出查询驱动的数据构建方案**：从多跳用户查询出发，依次进行工具创建、文档细化与代码生成，确保工具间存在有意义的依赖关系，并与已有工具驱动方法形成本质区别。
2. **构建 ToolHop 基准数据集**：涵盖 995 个多跳查询与 3,912 个可本地执行工具，覆盖 47 个领域，支持多样化查询、有意义依赖、本地可执行、详细反馈与可验证答案。
3. **系统性评测 14 个跨五大家族的大语言模型**：揭示当前模型在多跳工具使用上的显著局限（最佳模型 GPT‑4o 仅 49.04% 准确率），并为不同模型家族的调用策略差异提供深入分析。
4. **设计多维度评估体系**：从答案正确性（直接回答、强制工具使用、自由选择三种场景）与调用错误率（查询级与实例级）两个维度进行综合评估，为后续研究提供标准化评测框架。

## 方法详解
**形式化定义**：给定多跳查询 $q$，可分解为原子子查询 $q_1, q_2, \ldots, q_l$；工具集合 $\mathbb{T} = (t_1, t_2, \ldots, t_l)$，每个工具 $t_i$ 由文档 $\text{doc}$ 与代码实现 $\text{fun}_i$ 定义。模型需按顺序调用工具 $t_1 \rightarrow t_2 \rightarrow \ldots \rightarrow t_l$，其中每个工具的返回结果作为下一个工具的输入，最终得到答案 $a$。

**查询驱动的数据构建流程**（三个阶段）：
1. **工具创建（Tool Creation）**：将多跳查询 $q$ 分解为原子子查询序列，为每个子查询生成初步工具文档 $\text{doc}'_i$，文档间保持前后依赖关系，确保模块化与内聚性。
2. **文档细化（Document Refinement）**：扩展工具功能（如结果过滤、格式定制），增加参数数量并优化参数类型（将简单字符串替换为数组、对象等结构化类型），提升工具的表达能力与复杂度。
3. **代码生成（Code Generation）**：根据细化后的文档生成可本地执行的函数 $\text{fun}_i$，将原子查询及其答案作为输入验证函数正确性，并集成健壮的错误处理机制以提供详细反馈。

**数据集构建**：基于 MoreHopQA 数据集中的多跳问题，生成 995 个用户查询与 3,912 个可本地执行工具，通过上述流程确保数据集质量。

## 实验与结果
**数据集规模**：995 个多跳查询，3,912 个工具（每个查询需 3～7 个工具），覆盖 47 个领域。
**评估模型**：14 个大语言模型，涵盖 5 个家族（LLaMA3.1、Qwen2.5、Gemini1.5、Claude3.5、GPT），包括开源与闭源模型。
**评估设置**：三种场景——直接回答（Direct）、强制工具使用（Mandatory）、自由选择（Free）；错误指标包括查询级错误率（Query）与实例级错误率（Instance）。
**主要结果**：
- 使用工具平均提升答案正确性 12.29%，其中 GPT 家族提升 23.59%。
- **最佳模型 GPT-4o 在强制工具使用场景下准确率为 49.04%**，仍有巨大提升空间。
- 不同模型家族表现差异显著：Qwen2.5 家族倾向并行调用导致幻觉；Claude3.5 家族在直接回答场景依靠内部 CoT 推理取得优势；GPT 家族能从详细反馈中有效纠正错误。
- 模型规模与性能呈正相关，但调用错误与答案正确性的相关性在查询级更强。
**核心结论**：当前大语言模型在多跳工具使用任务上面临严峻挑战，需要更强的工具依赖理解、错误纠正与细粒度反馈利用能力。

## 相关工作脉络
1. **API-Bank、ToolAlpaca、RestBench**：这些工作大多采用工具驱动方法，工具间缺乏有意义的依赖关系，且不支持本地执行与详细反馈，无法评估多跳推理。
2. **ToolBench、MetaTool、TaskBench**：虽包含多工具场景，但未确保工具间的因果依赖，且答案不可验证或反馈不详细。
3. **T-Eval、ToolEyes、UltraTool、Seal-Tools**：部分支持本地工具或详细反馈，但缺少多跳依赖结构，或无法提供可验证答案。
4. **BFCL v3（multi-turn）**：唯一具备有意义依赖关系的基准，但缺乏本地可执行工具与详细反馈，仅支持一次性输出所有工具调用，不适合评估动态交互。
5. **本文定位**：ToolHop 是唯一同时具备多样性查询、有意义依赖、本地可执行工具、详细反馈与可验证答案五大特性的基准，专为多跳工具使用评测设计。

## 局限性与未来方向
1. **缺乏即时增强策略**：论文未提供如何直接提升模型多跳工具使用能力的具体方法，仅指出可通过本数据集进行针对性训练。
2. **数据集可扩展性待验证**：虽然数据构建方案具有可扩展性，但当前规模（995 个查询）相对较小，需进一步扩充以覆盖更复杂场景。
3. **依赖 GPT‑4o 辅助构建**：数据构建过程使用 GPT‑4o，可能引入模型偏好或偏差，影响数据多样性与客观性。
4. **未来方向**：基于本数据集构建训练数据以提升模型能力；进一步优化数据构建方案以降低对外部模型的依赖；扩展工具复杂度与交互深度。

## 研究启发与可借鉴点
1. **查询驱动的数据构建思路**：从用户查询出发逆向生成工具与代码，可保证任务的多跳结构与依赖真实性，适用于其他复杂能力评测基准构建。
2. **多维度评估设计**：同时考察答案正确性与调用错误率，并细分直接/强制/自由选择场景，为工具使用评测提供更全面的分析视角。
3. **详细反馈机制的价值**：引入可执行的错误处理与详细反馈，不仅提升评估可靠性，也为模型纠错能力研究提供可行路径。
4. **可本地执行工具的优势**：工具本地部署可实现零成本、高频调用，便于大规模评测与快速迭代，适合构建长期基准。
5. **跨模型家族对比分析**：揭示不同模型在工具调用策略（如并行调用、CoT 推理、反馈利用）上的差异，为模型优化提供针对性建议。

## 关键术语表
**Multi-hop tool use**：将复杂查询分解为多个原子子查询，顺序调用多个工具，并将前一步工具输出作为后一步输入，最终获得答案的过程。
**Query-driven data construction**：以用户查询为起点，通过工具创建、文档细化与代码生成三个阶段，逆向构建包含多跳依赖的工具数据集的方法。
**Tool hallucination**：模型调用了未在提供工具集中包含的工具的错误行为。
**Parameter hallucination**：模型为工具提供了文档中未定义的参数的错误行为。
**Parameter missing**：模型调用工具时遗漏了必要参数的错误行为。
**Chain-of-Thought (CoT)**：通过逐步推理分解问题以提升模型解题能力的提示技术，Claude3.5 家族在无显式提示下仍能自主使用 CoT。
**Function Calling (FC)**：大语言模型调用外部工具的标准接口模式，与 ReAct、CodeAct 等推理框架并列。
**MoreHopQA**：用于生成初始多跳查询的数据集，包含可分解为至少三个原子查询的问题及其答案。
